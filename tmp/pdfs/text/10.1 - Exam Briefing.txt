Course Goal
•   Learn software engineering principles via exposure to the
    important practice of building correct products in effectively
    functioning teams.
•   Build a strong foundation in the fundamental principles and
    practices of software engineering.


•   You can
    •   describe stages of software development lifecycle and
        implement them
    •   reason about good practices of software engineering
What you have learnt
•   Software Management – version control (git), teamwork

•   Software Process – SDLC

•   Software Project – package management, CI/CD,
    persistence, HTTP, auth, deployment

•   Software Veriﬁcation – static and dynamic veriﬁcation,
    coverage

•   Software Design – complexity, modelling, maintainability

•   Software Requirements – requirement engineering
Assessment
•   10% Labs

•   45% Project

•   45% Final Exam

To pass, you must:

- score 50/100 overall

- Score 18/45 (40%) on the ﬁnal exam

(For example, 55/100 overall, 17/45 on ﬁnal exam would result
in 55 UF not 55 PS)
Pass Rate
We manually inspect the work of students just below the pass
threshold.

- If we see many students who’ve suﬃciently shown
  competency with basic course material but not passing, the
  exam mark or other components may be scaled up.

COMP1531 is a challenging course, but pass rate is around the
same as the average for level 1 UNSW courses.
Lab Marking
Practical Lab

- 12 assessable (core) practical labs worth 0.75 mark each.

Theory Quiz

- 6 theory quizzes worth 0.5 marks each.

You only need to score 10/12 marks to achieve full marks in
the lab component.

The majority of students (>70%) get >= 9/10 marks in labs.

-Autotests will be available for most/all coding questions.

- Passing autotests does not guarantee any marks - do your

The Final Exam: Marking
-No marks awarded for style or comments for practical questions.

- But a human marker may need to be able to deduce the behaviour
  of your program

-And you should probably be able to read your own code

- Please use reasonable style, variable names, so that we can give
  you the mark that you deserve

-Comments only necessary to tell the marker something

-Do not include identifying info in comments
The Final Exam: Marking
-Answers will be run through automatic marking software.

    - Please follow the input/output format shown exactly - autotest
      is a guide to help you achieve this.

    - Please make your program behave as speciﬁed.

- Answers that don’t pass all automarking tests are handmarked,
  guided by automarking.
The Final Exam: Marking
-Minor errors will only result in a small penalty.

    - Eg. an answer correct except for missing whitespace would
      receive almost full marks.

- No marks given unless an answer shows substantial progress
  towards a solution (>33%)
    - No marks just for starting a question and writing some generic
      code.
    - Zero marks for submitting starter code.
