Compare benefits and downsides:
- Benefits:
  - Each feature is isolated, so unfinished or broken work does not affect the stable `master` branch.
  - A merge request allows review and automated tests before the feature is integrated.
  - Team members can work in parallel, and feature branches provide a clear place to collaborate and revert one feature.
- Downsides:
  - Creating, switching, reviewing, and merging branches adds process overhead compared with pushing directly to `master`.
  - Branches that are kept for a long time can diverge, causing merge conflicts and making integration slower or more difficult.
  - Directly pushing to `master` is simpler and exposes changes immediately, but it can make `master` unstable, allow mistakes without review, and make it harder to identify or undo one feature. Therefore, the branch-and-merge-request process trades some speed and simplicity for safer, more controlled integration.
